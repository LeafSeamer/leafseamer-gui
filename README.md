# LeafSeamer GUI

施工中。已提供可构建的简中／英文、浅色／深色工作台，经 SDK 接入 Controller 的人员登录、显式续期、退出、持久设备目录、人员接管／释放及查原、控制状态、当前设备能力与 Schema、隔离 OBS 手动 Cut、命令详情和固定修订证据分页读取。固定 Seamer 工作台支持草稿文档编辑、绑定来源审阅与批准／撤销、定义发布、固定版本读取和原请求恢复。当前交付限联调环境，控制转交、实时订阅、完整图形编排、自动运行、完整管理和部署安装仍待实现或验收。

## 构建与装配

使用 Node 24.22.0、npm 11.19.1。相邻 `leafseamer-sdk` 必须先构建为 [sdk-runtime.json](sdk-runtime.json) 固定的输入，安装采用锁文件。

```sh
npm ci --ignore-scripts
npm test
npm run build
```

无配置构建只生成未配置站点，不允许登录。实际装配先取得目标 Controller 业务库的持久 `service_id` 与 `database_instance_id`，在本地准备只含以下三个字段的 JSON 文件；两个标识填写该业务库的真实 UUID，不生成替代值。

```json
{
  "site_label": "本机 Controller",
  "service_id": "目标服务 UUID",
  "database_instance_id": "目标业务库 UUID"
}
```

运行 `npm run build -- --config <配置文件>` 生成 `dist`。附加 `--out-dir <尚未创建的绝对目录>` 可为这一站点生成独立产物。用 Controller 的 `supervise --pairing-profile` 启动时，在受信配置的 `gui` 中填入产物目录和 `gui-manifest.json` 原字节摘要。现有本地程序装配也可通过 `startController` 的 `guiDirectory` 提供产物。服务启动时校验 SDK 清单、站点实例和静态文件摘要，随后在 Controller 的 HTTPS 根路径提供已固定的资源。正式认证提供者和 TLS 安装按 Controller 与 Suite 的部署要求验收。

## 会话与读取行为

浏览器管理 `/auth` 路径的 Secure、HttpOnly、SameSite=Strict Cookie；CSRF 和定向 token 仅由 SDK 保存在内存。语言、主题保存在本机偏好中；控制请求发送前另外在本标签页的 sessionStorage 保存非秘密查原身份，密码提交后立即清空表单。刷新页面清空内存会话，不自动续期、重试或重发写入。

目录读取按同一修订分页，完整读取后才显示，最多64页／4096设备；修订变化、重复设备或游标停止本次读取。控制记录必须属于配置的服务及数据库，未读取与已知零值分别显示。所有数字版本保持十进制原文，读取时间是浏览器本地记录，不是权威认证时钟。页面展示最近读取结果，没有自动同步或设备完成保证。

选定设备后显式“读取能力”调用同源SDK `getCapabilities`，仅申请device.read。显示模块／版本、目录修订、动作、触发器、直接声明的参数范围及可展开的完整状态／参数／结果／前置条件Schema；完整文档仅在展开时渲染。设备连接状态使用该次能力响应，未读取或读取失败显示尚未读取，不把静态登记描述当作实时连接。作用范围不完整会明确标记，完整声明也不等于发布或执行资格。

能力读取核目标服务及单一设备身份／类型。切换设备、刷新目录、续期、退出或本地清理会清空能力；失败读取不保留上次结果，迟到响应不跨会话恢复。没有自动轮询、重试或发送设备动作。实际Edge与原生监督器／独立模拟器集成验证真实HTTPS能力、参数范围和键盘展开、断线503清除、新会话重连、目录刷新、英文深色窄屏及注销清理；首次环境资格仍为测试提供者，不能据此声明真实型号或完整编辑器已验收。

会话续期为显式操作，成功后清空设备视图；退出202只表示本地会话撤销已确认，远端传播仍待确认。网络异常时清空本页凭据，保留服务端结果未知的提示。无读取权限的账户不显示合成设备或假控制值。

命令记录通过已知命令标识查询，分别显示执行阶段、结果、设备效果和资源状态；`accepted_at: null`显示“无可信参考时间”，不会用浏览器时钟补值。命令读取使用`command.read`，证据另需`command.evidence.read`。证据页绑定当前读取记录的状态修订、快照、服务及数据库；偏移、总数、重复条目或游标不一致时拒绝显示。页面不自动轮询，换命令或续期会清空旧详情和证据；查找失败不会继续展示上一条命令。历史状态不授予当前设备写入资格。

## 人员接管与释放

选择设备并填写原因后先准备，再明确确认。准备读取当前控制版本、签发上下文并固定请求身份，不写控制；确认只发送一次，使用该上下文绑定的原令牌。其他操作若需更换令牌会取消未提交草稿。服务端继续检查当前人员权限、撤销、版本和原截止；紧急接管需明确选择且具备对应权限。

提交前必须成功保存查原身份，存储不可用时不发送。sessionStorage 仅包含操作名、设备标识和完整 RequestIdentity，不含请求正文、凭据或可重放队列。同一人员的 issuer、epoch、principal 三元组重新登录后可查询原请求及操作；未找到仍不能换新键重发。更换人员、显式退出或关闭已确认记录会清除本页关联；离开页面不会释放控制。

受理回执、控制操作状态和当前持有人／闸门分别显示。接管或释放生效后仍可能为 protected，历史成功不授予设备写入资格。当前内存令牌仅在权限范围满足且 expires_in 提示未到期时复用，计时从签发调用前开始；后端每次请求重新校验，拒绝后不自动重试。断线丢失响应有状态测试覆盖，真实浏览器覆盖正常接管、刷新查原与释放。

## 隔离 OBS 场景切换

选择 OBS 设备并读取场景状态。授权人员确认当前目录并开闸后，当前控制持有人可选择目标，提交一次即时 Cut。提交前重新读取确认目录和手动控制状态。受理回执只表示请求已登记，可通过“查询切换结果”查看执行与资源状态，再到命令记录读取完成和释放证据。保护态禁止提交。断连后读取失败会清除旧场景。

切换发送前在本标签页保存服务、库和人员绑定的查原身份，以及拒绝原受理所需的动作内容与操作标识。响应中断后可重新登录查原。查无原件时，具备 `command.cancel` 的原人员可明确确认“阻止原请求受理”。Controller 原子地封存原键或返回已先提交的受理。旧版只保存查原身份的记录继续支持查询。目录确认与开闸由 Controller 人员流程完成。

`test/controller-obs-browser-check.mjs` 由 Suite 的 OBS 原生联调用例驱动，验证 Edge 通过真实 HTTPS 提交 Cut、读取结算结果，以及保护和断连后的界面状态。设置 `LEAFSEAMER_OBS_BROWSER_RECOVERY=1` 可验证原请求在浏览器内中断后的再次登录、查原与显式拒绝。

## 验证范围

类型检查和状态管理测试覆盖目录与证据分页一致性、精确服务归属、大整数、权限不足及撤权、迟到响应、并发抑制、失败退出、控制上下文原令牌绑定、丢失响应后查原、存储故障及令牌复用／到期。Controller 侧另测静态资源摘要／路径／身份校验、HTTPS限制、HEAD及CSP。

`test/browser-check.mjs` 使用相邻 Controller 的隔离夹具启动真实 HTTPS、SQLite 和原生采样器，再通过独立 Edge 运行十项浏览器检查：登录成功和失败、Cookie限制、设备读取、键盘焦点、显式续期、语言主题、窄屏、退出及权限／资格失效。显式传入已安装 Playwright 的模块入口和 Edge 可执行文件路径；测试仅信任夹具临时证书公钥，不修改系统证书库或用户浏览器资料。产物位于忽略的 `logs/gui-session`。

`test/command-browser-check.mjs`验证真实HTTPS登录、令牌与不存在命令查询，以及合成命令成功响应的SDK解码、null时间展示、固定修订证据分页、双语／主题、1440与390像素布局和错误响应后的清理。成功命令与证据通过显式测试路由提供，不证明实际设备执行或完整命令集成。产物位于忽略的`logs/gui-command`；主动注入的错误与意外控制台错误分别记录。两个浏览器脚本均按`node <脚本> <Playwright模块入口> <浏览器可执行文件>`调用，浏览器驱动不使用`--disallow-code-generation-from-strings`；该参数会使当前Playwright的页面读取失效。产品运行参数不因此改变。

`test/controller-command-browser-check.mjs`由Suite的同设备双命令用例驱动，连接同一受监督Controller进程的实际HTTPS和SQLite记录。浏览器不拦截请求：两条模拟器命令的第5修订、完整记录摘要、完成／释放证据及其快照引用须与实际执行原件一致；服务端撤销证据权限后，再次读取返回401／403并清除旧证据；401同时清除本页会话。1440像素中文浅色和390像素英文深色页面均已验证，结果保存到忽略的`logs/gui-execution`。这是固定内存模拟器到浏览器的完整读取验证，不是实际设备或生产部署验收。

运行该集成时，在Suite现有`controller-materialization.integration.mjs`双命令用例上显式提供`LEAFSEAMER_GUI_TEST_ROOT`、`LEAFSEAMER_PLAYWRIGHT_MODULE`和`LEAFSEAMER_BROWSER_EXECUTABLE`三个绝对路径，另按Suite要求指定`LEAFSEAMER_CONTROLLER_TEST_ROOT`。仅命令读取测试名称以`_dispatch_closure_cleanup_successor`结尾；追加`_control`会验证准备取消、键盘确认接管、刷新登录后按原身份查原、释放及保护状态。用`LEAFSEAMER_BROWSER_ARTIFACTS`指定仓库外的绝对产物目录，可查看控制界面桌面／窄屏截图和网络检查结果。Suite先构建绑定临时业务库身份的GUI，再运行模拟器和浏览器；不要同时运行其它会覆盖GUI构建目录的任务。

上述浏览器成功使用合成环境批准、账户和设备，不代表平台批准、真实设备、正式部署或完整 UIT01—UIT40 验收。当前 SDK 完整静态校验器使脚本约8.4 MB，窄带首次加载尚待优化和验收。完整范围与退出条件见 Suite 的整体完成清单。

## Seamer草稿工作台

构建配置可显式增加 `seamer: {service_id, database_instance_id, base_url, service_label}`，产物采用 `leafseamer.gui.site/2`；base_url为规范HTTPS origin或其 `/services/<固定标识>` 前缀，不带末尾斜线。旧配置仍生成site/1并显示未配置自动化服务。Controller固定清单后仅开放该Seamer origin的连接；Seamer装配也须明确允许Controller页面origin。页面不从URL参数或输入框修改服务目标。

人员登录后，“自动化”页支持按定义标识读取、创建草稿、分别保存内容与名称／描述。定义内容可导入JSON文件或直接编辑，当前上限4MiB；现为完整内容文档编辑入口，图形编排、条件编辑器及完整语义诊断界面尚待实现。内容与元数据分别使用所读修订进行CAS，不把保存当发布或运行。父客户端响应预算显式为8MiB，服务端仍独立裁决正文容量与权限。

每次写入先取得适用的定向令牌与新context，再通过SDK准备原请求身份；页面成功保存并读回sessionStorage中的非秘密查原身份后才发送。保存内容和凭据均不进入该恢复记录。记录按目标服务／数据库及issuer／epoch／principal隔离；未确认前阻止新写入，不保存自动重发队列。重新登录可查询原结果，校验操作、摘要和目标；原历史结果必须读取当前草稿后才能编辑。404／拒绝／错摘要保留未确认身份，不能推断写入未发生。页面离开或迟到响应不会恢复旧会话。

`test/seamer-draft-browser-check.mjs`由Seamer的实际双进程测试驱动，使用本机Controller与Seamer真实HTTPS、SQLite和配对链。通过环境显式提供Playwright、Edge与外部截图目录；Browser插件不可用时采用已有Playwright，不安装依赖或改动系统证书库。实际浏览器验证创建、两类编辑、CORS读取、已提交响应丢失后的重载登录与只读查原，以及1440像素中文浅色／390像素英文深色布局。仅故障注入阶段在真实提交后中断响应；首次配对、首个本地管理员和环境资格仍为测试预置，不能作为首次部署验收。

在 Seamer 的 `first-pairing-import.test.mjs` 中设置 `LEAFSEAMER_GUI_PLAYWRIGHT`、`LEAFSEAMER_GUI_BROWSER` 和 `LEAFSEAMER_GUI_OUTPUT` 的绝对路径，可从首次配对继续验证草稿。该用例使用新建业务库，由 Controller 和 Seamer 的独立 CLI 完成配对、首位管理员批准和两端权限登记，再通过实际 Edge 登录。它还验证 Seamer 重启后读取旧草稿，以及已提交响应丢失后查询原请求。环境时钟和证书仍采用受控测试材料。

## 查询运行状态

在「自动化」页输入运行标识并选择「查询运行」。界面显示 Seamer 最近一次返回的生命周期、派发资格、定义版本、运行修订及执行标识。查询需要该 Seamer 的 `run.read` 权限，结果随会话续期、退出和再次查询清除。

## 定义发布与固定版本读取

已读取的当前草稿可准备发布，显示定义、内容修订及内容／选择摘要；未保存修改、历史查原草稿或未确认写入会阻止确认。准备和取消不签发凭据或访问网络。确认时使用具备发布权限的定向令牌及新Seamer独立context，先保存非秘密查原身份再发送一次；发布成功不布防或运行。刷新会话、重新读取或编辑草稿会清除旧准备。

发布响应不确定时，保留原请求身份；重新登录只查询原结果，核对操作、摘要、定义、原草稿修订及发布人员，不假定版本连续，不自动再发布。固定版本读取校验artifact、完整程序、绑定和独立性证明的摘要关联；历史视图带读取时间，不代表当前来源或设备仍可执行。切换证明选择不会把旧证明显示为新选择的结果。

真实双进程浏览器测试包含发布、原件读取与已提交发布响应丢失后的查原恢复。测试采用真实人员登录、定向令牌、配对身份核验、HTTPS和SQLite；首个配对管理、环境资格、绑定注册与覆盖批准原件仍为明确的合成测试提供者。该发布用例不证明真实权威来源与发布的完整集成，也未完成布防、运行或真实设备验收。绑定批准界面及其独立验收见下文。

Suite 的 `successor_capture_events` 联调可从首次配对继续验证实际模拟器来源的浏览器发布。配置 `LEAFSEAMER_PUBLICATION_GUI_TEST_ROOT`、`LEAFSEAMER_PLAYWRIGHT_MODULE`、`LEAFSEAMER_BROWSER_EXECUTABLE` 和 `LEAFSEAMER_BROWSER_ARTIFACTS` 的绝对路径，由联调构建本次站点配置并启动 Edge。首次授权经 Controller 签发，由 Seamer 使用停机 CLI 导入并单次消费。同一配对的事件与动作绑定获批后，浏览器登录、打开草稿、发布并读取固定版本，校验制品和编译程序，截图保存到指定外部目录。联调使用受控证书、时钟证据与临时数据库。

## 绑定来源审阅、批准和撤销

可信构建配置的 `seamer` 可增加 `binding_source: {binding_id, devices: [{device_id, label}]}`，生成显式 `leafseamer.gui.site/3`。`binding_id` 是 Seamer 一侧的本地配对标识；设备列表必须与已批准配对的读取用途和精确设备 scope 一致，取1至64个不重复UUID，标签最长120字符。Controller服务／数据库取站点根身份，不由界面输入。配置和设备项固定并深冻结；旧site/1、site/2仍支持，旧版本不能混入新字段。site/3上限32KiB，旧版本仍4KiB，未知字段及重复设备拒绝装配。

先创建或读取当前草稿，再从固定设备列表读取候选，展开完整来源／动作／作用范围并勾选审阅。准备和取消均不访问网络；确认批准时取得当前人员定向权限和独立context，重新读取精确注册并核对审阅摘要。来源变化或权限失效由服务拒绝，页面不自动换来源或重试。批准只用于该定义编译，尚未自动替换草稿的绑定选择，也不授予发布、布防或设备写入资格。

当前批准可明确准备并再次确认撤销；撤销只说明新的本地采用被拒绝，不能据此声称运行保护已完成。发送前保存并读回按服务／数据库／人员隔离的非秘密原请求身份，不保存token、CSRF、context或来源正文。响应不确定时清空内存会话，保留原请求；重新登录只查原，查不到仍保留且不重发。历史结果必须重新读取当前批准后才能准备撤销。

## 草稿绑定选择
